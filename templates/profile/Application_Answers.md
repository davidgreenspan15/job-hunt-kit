## Hard rules
- Truthful answers only. Why: an application is a signed statement; a false answer can end an offer later.
- A blank beats an invented answer. If a required question isn't covered here, stop and ask the user, then add the answer to this file so it's covered next time.
- Never pick a "How did you hear about us" channel the user didn't actually use. Use the real source from the tracker's Source column.
- Never invent a referral, a contact name, or a prior conversation.
- Free-text questions ("Why this company?") get a short, specific answer drawn from the cover letter, and they're shown to the user before submit.

## Pre-interview assessments / challenges
- Always surface take-homes, coding challenges (CodeSignal, HackerRank, and similar), and cognitive or personality tests to the user, along with the role's comp and the deadline. Why: the time cost is real, and only you can judge whether the role is worth it.
- The user decides case by case. Never auto-decline, and never start a timed assessment without the user's go-ahead.
- Log the assessment and its deadline in the tracker (Status "Action Needed", Next Action + Next Action Due).
